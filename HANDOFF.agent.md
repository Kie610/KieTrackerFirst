- C: Owner measurement of 2026-08-03 (unpowered multimeter): `SDA`, `SCL`, `SDO`, and `CS` each read 4.6 kOhm to `3V3`, so the module carries its own 4.7 kOhm pull-ups on all four. SA0 and CS are held high without wires, which is why the device answers at `0x6B`, and no external I2C pull-up is needed. Module wiring is therefore `3V3`, `GND`, `SDA`, `SCL` only. The top-side `SDO` jumper is open and its free pad is continuous to GND, so it selects `0x6A` and must stay open.

It said a USB-based run was impossible because the firmware cleared the counters on any start that was not an EXT0 wake. - C: 2026-08-05 — root cause of why the accel bias step never runs, found after three flash cycles. It is not the tilt tolerance and not rest detection: the step is **structurally unreachable in steady state**. Its only entry point is the `GYRO_BIAS` case of `stepCalibrationForward`, which runs only when the gyro bias step returns `DONE`. But `GyroBiasCalibrationStep::processTempSample` (`:133-142`) resets `gyroSums`, `sampleCount`, **and `startMillis`** whenever `gyroPointsCalibrated == 1` and the current temperature is within `gyroBiasTemperatureDifference` = 5 degrees of the stored point. Completion needs `gyroBiasCalibrationSeconds` = 5 s since `startMillis`, so at a stable temperature the timer is rewound forever and the step never completes. This tracker stores `29.656250C` and runs at that temperature, which is why every boot prints the identical gyro bias and nothing downstream ever fires. Loosening the `gyroPointsCalibrated == 1` transition condition therefore had no effect — the function containing it is never called.
- C: 2026-08-05 — the escape route, if the accel step is ever wanted. `GyroBiasCalibrationStep::tick` (`:62`) completes after 5 s of rest with no temperature check when `gyroPointsCalibrated == 0`, so erasing sensor calibration (serial `DELCAL`, which calls `configuration.eraseSensors()`) opens the gate once. Only one such completion is needed: after the first axis finishes, `stepCalibrationForward`'s `ACCEL_BIAS` case sets `skippedAStep`, and `tick`'s `skippedAStep && !lastTickRest && restDetected` path re-runs `computeNextCalibrationStep`, which returns to `ACCEL_BIAS` for the remaining axes without another gyro completion. - C: 2026-08-05 — how `AccelBiasCalibrationStep` actually works, since it is not the six-face procedure the earlier note assumed. It runs opportunistically at rest, after gyro bias calibration.
