# 敵対的レビュー 2026-08-07

## 所見(重要度順)

### F1 — `lib/i2cscan/i2cscan.cpp` の `#elif defined(ESP32S3)` が SuperMini を巻き込む(バグ・他ボード影響)

- 場所: `lib/i2cscan/i2cscan.cpp:38`(portArray 選択)と `:74`(`selectNextPort` の早期終了)。
- 事実(C): `platformio.ini:258` で `BOARD_ESP32S3_SUPERMINI` も `-DESP32S3` を定義する。そのため SuperMini の診断スキャンも portArray `{5, 6}`・ラベル `"D4","D5"` になる。しかし SuperMini の配線は `board-defaults.json:583` で `sda=7, scl=6` であり、GPIO7 は一切スキャンされない。ラベル名も XIAO の呼称で誤解を招く。
- 影響: SuperMini でセンサーが見つからないときの診断スキャンが実配線を走査できず、必ず「No I2C devices found」相当になる。AGENTS.md の「他ボードの挙動を保存する」方針に反する。
- 修正案: `:38` の条件を `#elif BOARD == BOARD_XIAO_ESP32S3` に狭める。SuperMini を含むその他の ESP32 系は従来の汎用 `#elif defined(ESP32)` 分岐へ戻す。`:74` は既に `BOARD ==` 条件なので変更不要。

### F2 — `SensorBuilder.h` の検出スキップが optional センサーの挙動を全ボードで変える(挙動変化・他ボード影響)

- 場所: `src/sensors/SensorBuilder.h:322-328`。
- 事実(C): `SoftFusionSensor` は全 IMU 型で `PerformsCheckedDetection = true`(`softfusionsensor.h:208`)なので、`hasSensorOnBus()` の事前確認が全ボードの全 SoftFusion センサーで省略される。上流では optional センサーが不在のとき静かに `EmptySensor` を返していたが、本フォークでは実センサーを構築して `motionSetup()` が失敗し、ERROR ログと `SENSOR_ERROR` 状態になる。
- 影響: IMU 2 個構成(拡張トラッカー等)の他ボードで、不在の optional センサーが「無し」ではなく「エラー」として報告される。本フォークの XIAO(単一・必須センサー)には影響しない。
- 修正案: optional のときは事前確認を維持する。最小変更は `:328` を `if ((!performsCheckedDetection || sensorDef.optional) && !sensorDef.imuInterface.hasSensorOnBus())` にする。詳細診断が要るのは必須センサーの失敗時であり、optional の不在は静かなスキップが正しい。

### F3 — `Sensor::setAcceleration` が毎サンプル `inverse()` を計算する(無駄な処理)

- 場所: `src/sensors/sensor.cpp:41`。
- 事実(C): `sensorOffset` はコンストラクタ(`sensor.h:67`)で一度だけ設定され、以後再代入されない。それにもかかわらず加速度サンプルごと(LSM6DSV で 120 Hz)に `sensorOffset.inverse()` を計算している。
- 修正案: `Sensor` にメンバ `Quat sensorOffsetInverse`(コンストラクタで `sensorOffset.inverse()` を計算)を追加し、`setAcceleration` はそれを使う。数値結果は同一で、フレーム修正(2026-08-06 に実機検証済み)の意味は変えないこと。

### F4 — `PowerButton.h` のコメントが実装と矛盾(ドキュメント腐敗)

- 場所: `src/power/PowerButton.h:12`「counters held in RTC memory」。
- 事実(C): カウンタは 2026-08-06 に NVS(`Preferences`、namespace `powerbtn`)へ移動済みで、`PowerButton.cpp` 側のコメントは RTC メモリを捨てた理由まで説明している。ヘッダだけが古い。
- 修正案: ヘッダのコメントを NVS 実装に合わせて書き直す。

### F5 — 代替アドレス解決ロジックの重複と `detected()` の成功ログ重複(保守性)

- 場所: `src/sensors/softfusion/softfusionsensor.h:209-214` の `AlternateAddress` ラムダは `include/sensor_address_resolver.h` の `resolveSensorAddress` と同一規則の二重実装。また `detected()`(`softfusionsensor.h:55` 以降)には「Connected to ...」info ログのほぼ同一ブロックが 2 つある。
- 修正案: `AlternateAddress` は `resolveSensorAddress<SensorType>(true)` で導出する。成功ログはヘルパー(ラムダまたは private 関数)へ一本化する。挙動・ログ文言は変えないこと。

### F6 — `main.cpp` の 2 秒シリアル待ちが毎回のボタン起床に上乗せされる(改良提案・要オーナー判断)

- 場所: `src/main.cpp:73-78`。
- 事実(C): ホスト未接続時は `while (!Serial ...)` が必ず 2 秒フルに回る。Deep Sleep からの起床はフルブートなので、ボタン起床のたびに最大 2 秒の遅延が加わる。トレードオフとして、この待ちがあることで USB 接続時に起動直後のログが失われない。
- 提案(A): `esp_sleep_get_wakeup_cause() == ESP_SLEEP_WAKEUP_EXT0` のときは待ちをスキップする(起床時にホストが繋がっている運用は例外的で、繋がっていれば次のログから読める)。採否はオーナー判断。

### F7 — `platformio.ini` の XIAO 2 環境がほぼ全行重複(保守性)

- 場所: `platformio.ini:191-247`。
- 事実(C): `BOARD_XIAO_ESP32S3` と `BOARD_XIAO_ESP32S3_400KHZ_DIAGNOSTIC` は platform、platform_packages、board、build_flags の大半、test_filter が重複しており、差分は `I2C_SPEED` と `LOG_LEVEL` だけ。片方だけ直す事故の温床になる。
- 修正案: 共通部を `[xiao_esp32s3_common]` セクションへ出し、両環境で `extends` する。生成される `-D` フラグ集合が変わらないことを `pio run -v` などで確認すること。
